# Boss URL 与功能对照

本文件记录 boss-cli 已知页面 URL、对应命令和当前位置要求。修改页面导航、命令入口或报错文案前，先对照这里，避免把某个命令改成隐式跳转或多路径兜底。

## 页面 URL

| URL / Path | 页面功能 | 相关命令 | 当前行为 |
| --- | --- | --- | --- |
| `https://www.zhipin.com/web/user/?ka=header-login` | 登录入口 | `boss login` | 直接打开登录页，交还给人工扫码/验证。 |
| `/web/chat/index` | 沟通列表、候选人会话页 | `boss list`、`boss list --unread`、`boss chat <姓名>`、`boss chat [姓名] --index <序号> [--unread]`、`boss send`、`boss action` | `list` / `chat` 会先检查当前位置，不在该页时直接进入；`chat --index` 使用 `boss list` 输出的 1-based 序号，带 `--unread` 时使用 `boss list --unread` 输出的序号；同时提供姓名时会校验序号对应候选人姓名，适合处理同名候选人；`send` / `action` 要求当前会话已打开。 |
| `/web/chat/recommend` | 推荐候选人列表 | `boss recommend`、`boss preview <姓名>`、`boss greet <姓名>` | `recommend` 会先检查当前位置，不在该页时直接进入；`preview` / `greet` 要求当前已在该页且列表已加载。 |
| `/web/chat/aiform` | 深度搜索 / Agent 搜索 | `boss deep-search [--core <要求>] [--bonus <加分项>] [--clear-core] [--clear-bonus] [--match]`、`boss preview <姓名>`、`boss greet <姓名>` | `deep-search` 会先检查当前位置，不在该页时直接进入；默认只输出招聘要求表单、核心要求、加分项、今日剩余匹配次数和按钮状态，不输出候选列表；`--core` / `--bonus` 可重复，并按传入列表同步对应分组（多余行会删除，不足会新增），`--clear-core` / `--clear-bonus` 清空对应分组；只有 `--match` 会消耗今日匹配次数并输出列表顶部最新 20 条；`preview` / `greet` 要求当前已在该页且列表已加载。 |
| `/web/chat/search` | 常规搜索 | `boss search [关键词]`、`boss preview <姓名>` | `search` 会先检查当前位置，不在该页时直接进入；带关键词时填入搜索框并回车搜索；`preview` 要求当前已在该页且列表已加载，不支持 `--job`。 |
| `/web/chat/job/list` | 职位管理列表 | `boss positions`、`boss jd <name>` | 可通过侧栏进入职位管理页后读取。 |

## 约定

- 当前 URL 校验优先于 DOM 猜测。命令依赖特定页面时，先检查 path，再执行页面读取或点击。
- 不为高风险操作添加隐式兜底跳转。需要用户处于特定页面的命令，应直接报出当前 URL 与目标 URL。
- 页面入口发生变化时，同步更新本文件和相关命令 help 文案。

## 本地候选人工作台

- `npm run ui`：编译并启动仅监听 `127.0.0.1:3210` 的工作台，可用 `BOSS_UI_PORT` 显式修改端口。与 `landing/` 官网独立。
- 本地 `/` 展示登录入口、岗位推荐、关键词搜索、候选人简介和完整简历图片。
- 本地 `POST /api/command` 只接受 `login` / `recommend` / `search` / `preview`，通过子进程调用当前编译后的 CLI。需要同源校验和会话令牌，同一时间只执行一项操作。
- `boss login --json` 返回登录页打开结果，**不表示已登录成功**。
- `boss recommend ["岗位关键词"] --json` / `boss search ["关键词"] --json` 返回 `{source, context, candidates}`。候选人包含姓名、列表可见简介、经历、教育等信息和内容校验 `token`；未提供字段为空，不推断或补全。
- `boss preview "姓名" --json --source recommend|search --token <token>` 返回 `{name, imagePath}`，明确关闭 OCR，仅生成本地图片。必须仍在指定来源页且姓名、年龄、毕业／经验标签与学历的组合唯一、候选人内容与 token 一致；不自动导航，变化时直接报错，要求重新加载列表。结构化预览暂不支持深度搜索来源。
- 工作台 JSON 预览按 token 取出当前卡片，再用姓名＋年龄＋毕业／经验标签（如 28 年应届生、3 年）＋学历校验唯一性并执行点击；四项均相同则报错。`--age` 保留额外年龄校验。活跃状态不参与定位，token 仍校验列表内容。
- 工作台仅在点击查看完整简历后调用预览；当前页面内重看已加载图片不重复调用。刷新工作台会清除前端列表和图片引用，截图文件仍在本地。
- `GET /api/local/resume/<随机标识>` 仅提供数据库登记的简历 PNG，不接受客户端文件路径；简历引用可跨服务重启使用。旧版 `/api/resume/` 临时引用已停用。

- `GET /api/events` 通过 SSE 推送当前操作名称和忙碌状态，所有工作台页面在操作期间禁用提交；操作完成恢复按钮，不自动重复执行失败命令。状态连接中断明确提示刷新。并发冲突单独提示，不推断为登录失效。

- 推荐简历入口使用精确定位后的 `.card-inner` 元素，通过浏览器原生点击触发 pointer/mouse 事件；不使用 DOM `click()`，不尝试多个按钮入口。未找到卡片主体直接报错。
- 简历截图临时将布局视口宽度扩展到至少 1440px，按 iframe 的页面坐标截图，避免窄视口下侧栏遮挡与二次滚动造成裁切；完成后恢复打开前的视口。

- JSON 命令失败时以非零退出码在 stdout 返回 `{error, code}`；候选人不在当前列表、来源或内容变化返回 `STALE_LIST`，真正重名返回 `AMBIGUOUS_CANDIDATE`。工作台在列表失效后禁用旧记录的新预览，提供显式“重新加载候选人”，不自动重试或替换人选。

## 本地数据库与批量采集

- 浏览器连接与登录不再调用 `bringToFront`；无现有标签时创建后台标签。Chrome 启动使用 `--no-startup-window`。登录需用户自行切换到 Chrome。
- 工作台每次成功读取列表均写入 `~/.boss-cli/data/candidates.sqlite`（可用 `BOSS_DATABASE_DIR` 指定目录）。保存全部返回字段和观察历史；平台 ID 在同一来源内更新记录，无 ID 时独立保存，不按姓名合并。
- 查看简历成功后，将 PNG 复制到数据目录的 `resumes/`，记录版本及更新时间；重启后仍可通过 `/api/local/resume/<id>` 查看。OCR 保持关闭，不声称已提取图片中文字。
- `GET /api/local?q=&offset=0` 查询本地候选人，每页 100 条；本地候选人页不操作 Boss。
- `POST /api/batch` 接受 `source` 和 `keyword`：加载一次当前来源列表并保存，然后逐人预览，间隔 15–25 秒。达到数量前向下滚动加载更多候选人。通过 SSE 展示进度。
- `POST /api/batch/stop` 中止等待；正在执行的简历会完成保存后停止。简历未打开按下文规则重试，单人错误记录原因并继续下一位，已保存的数据不删除，不发送消息。
- 批次在服务进程内运行，刷新页面可重新看到进度；服务终止后不自动续跑，已完成的数据保留。

### 批量数量与续采

- `POST /api/batch` 新增 `limit`，默认 30，须为 1–500 整数。目标按新增完整简历数计算；`completed` 为新增数、`skipped` 为跳过的已有简历数。
- 同一来源的平台 ID 若已关联本地简历，跳过详情点击；只有简介的候选人补采详情。批内已访问的 ID 不重复处理；缺少 ID 直接报错，避免误合并。
- `boss list-more --json --source recommend|search` 仅在对应来源页继续向下滚动并读取列表，不导航、不重选岗位、不重新提交关键词。每次小幅滚动后等待 0.9–1.4 秒，最多 45 秒；滚动到底后等待 6 秒仍无新候选人，明确报错并结束批次，不把不足数量报告为达标。
- 续采过程显示“正在向下滚动”；停止请求会在当前 CLI 操作结束后生效，已采集的数据保留。

### 简历未打开时自动重试（用户明确要求）

- 仅 `RESUME_NOT_OPENED`（点击后未出现 c-resume iframe，且未检测到付费/额度弹窗）触发批量自动重试。CLI 保留结构化错误码。
- 每次重试等待 15–25 秒；通过 `boss list-current --json --source recommend|search` 重新读取当前来源列表，按平台 ID 唯一匹配同一人，更新 token 后再预览。该命令不滚动、不导航、不重选岗位。
- 最多额外重试两次（共三次尝试），保留原批次目标、已完成数和数据库记录。等待中允许停止；身份、登录、额度或其他错误不进入此重试路径。
- 界面显示重试状态及次数；日志记录批次、平台 ID、错误原因及重试次数。超过上限记录该人的失败原因并继续下一位，保留成功数据。

- 滚动容器选择：卡片内层可滚动祖先优先；到达 body/html 时使用 `document.scrollingElement`，避免将传播到视口的 body overflow 误判为独立滚动容器。位置未移动且尚未到底部时报告滚动限制，不报告“已到底”。

### 单人错误不中断采集

- 批量采集使用姓名＋年龄＋毕业／经验标签＋学历校验唯一性，同时继续按平台 ID 去重和按 token 校验列表内容。四项组合不同可以分别采集；四项完全重复、缺年龄或缺平台 ID 均记录失败原因，跳过该人。
- `failures` 返回失败候选人的姓名、年龄与原因，页面提供可展开的失败清单。失败不计入成功目标；预览、重试或单人保存失败后继续下一位，每次真正打开前仍保留等待间隔。
- 读取列表、滚动或整个数据库不可用属于无法继续的批次级错误，会说明原因并保留已完成数据；不会伪报达到目标或无限空转。

## 飞书同步

- 本地候选人页的“一键同步到飞书”通过 `POST /api/feishu/sync` 启动后台同步，需同源和会话令牌校验，与批量采集互斥；状态通过 SSE 的 `feishuSync` 返回。只点击按钮才同步候选人，服务启动不会自动上传。
- 服务端配置为 `~/.boss-cli/feishu.json`（权限 0600）：`appId`、`appSecret`、`wikiToken`、`tableId`。密钥不返回浏览器、不放仓库。通过 wiki 节点解析实际多维表格标识。
- 字段：姓名（文本）、年龄（数字）、毕业／经验标签（文本）、学历（文本）、简历附件（附件）、同步标识（文本）。缺少字段则创建，类型不符直接报错；默认主字段“文本”可改名“姓名”。
- 全量读取本地候选人（不受搜索条件或当前 100 条分页限制），筛选已有简历的记录，每批最多 50 条。先分页读取飞书同步标识，已存在则跳过，不更新或覆盖原记录。标识为来源＋平台 ID，无平台 ID 时使用本地 UUID；不凭同名合并。
- 简历附件为本地最新 PNG，逐份上传后写入对应记录。尚无简历的候选人不上传，页面显示无简历排除数量；以后已有记录仍会跳过，不自动补传或更新附件。
- 写入前把完整批次及 UUID 请求标识保存到本地 `data/feishu/`；结果未确认时停止并保留待确认批次，再次点击会使用同一请求标识确认，防止响应丢失造成重复写入。失败明确显示接口与错误码，不静默重试。
- 飞书应用需要知识库节点读取、多维表格字段与记录读写、云文档素材上传权限，并拥有目标表协作者权限。

- 简历获取失败保存到本地 `resume_failures` 表：候选人 ID、原因、错误码和发生时间。手动预览、批量身份校验及最终重试失败均记录；成功获取后清除该人的失败状态。本地列表 API 返回 `resumeFailure`，详情显示原因和时间。历史未记录的原因不推测补填。
